# Requirements Document

## Introduction

Extend the SMPL beta regressor from 4 demographic inputs (height, weight, age, gender) to 8 inputs by incorporating user-provided body measurements (chest, waist, hip, inseam) as direct regression features. The current demographics-only regression has a fundamental accuracy ceiling — round-trip errors are 8–14cm for chest/waist/hip because two people with identical demographics can have wildly different body shapes. The existing SHAPY calibration pipeline already generated a calibration dataset of 7,500+ (measurements → betas) pairs at `scripts/data/calibration_dataset.json` that includes chest, waist, hip, shoulder, and inseam alongside the 10 betas. This spec trains a new 8-input regression model from that dataset, updates the runtime regressor to use it when custom measurements are available, and preserves the existing 4-input path as a fallback.

## Glossary

- **Eight_Input_Regressor**: An extended regression model in `smplRegressor.ts` that maps 8 normalized inputs (height, weight, age, gender, chest, waist, hip, inseam) plus derived interaction terms to 10 SMPL beta parameters, trained from the Calibration_Dataset.
- **Four_Input_Regressor**: The existing demographics-only regression model that maps 4 inputs (height, weight, age, gender) plus derived terms (BMI, height×weight, BMI²) to 10 SMPL betas. Stored in the current `calibrated_coefficients.json` under the `regression` key.
- **Calibration_Dataset**: The 7,500+ entry JSON file at `scripts/data/calibration_dataset.json` containing per-subject heightCm, weightKg, age, gender, chestCm, waistCm, hipCm, shoulderCm, inseamCm, and 10 SMPL betas, generated by the completed SHAPY calibration pipeline.
- **Extended_Coefficient_Table**: The updated `calibrated_coefficients.json` file containing both the Four_Input_Regressor weights (under `regression`) and the Eight_Input_Regressor weights (under a new `regression8` key), plus all existing fields (presetOffsets, compositionBias, sensitivityMap, fatDistribution).
- **Coefficient_Trainer**: The Python script `scripts/train-beta-coefficients.py` that trains regression models from the Calibration_Dataset and exports the Extended_Coefficient_Table.
- **SMPL_Regressor**: The `smplRegressor.ts` module containing `lookupRegress()`, `computeSmplBetas()`, and the layered beta pipeline.
- **Measurement_Extractor**: The `measurementExtractor.ts` module that computes circumferences from the deformed SMPL mesh at anatomical cross-sections.
- **SMPL_Forward_Pass**: The `smplForwardPass.ts` module that computes vertex positions from beta parameters: V = T + Σ(βᵢ × Sᵢ).
- **Round_Trip_Error**: The absolute difference (in cm) between an input measurement and the measurement extracted from the SMPL mesh after the full pipeline: input → regressor → betas → forward pass → mesh → measurement extraction.
- **Hybrid_Regression**: A regression strategy used when the user provides 1–3 (but not all 4) custom measurements. Missing measurements are imputed from demographics using the Four_Input_Regressor's predicted values, then the Eight_Input_Regressor is applied with the combined real + imputed inputs.
- **Measurement_Imputer**: A function that predicts missing custom measurements from demographics using the existing `predictMeasurementsFromDemographics()` or ANSUR II lookup, providing fill-in values for the Hybrid_Regression path.
- **Body_Store**: The Zustand store (`bodyStore.ts`) holding `UserInputs` including optional `bustCm`, `waistCm`, `hipCm`, and `inseamCm` fields.

## Requirements

### Requirement 1: Extended 8-Input Regression Model Training

**User Story:** As a developer, I want to train an 8-input regression model from the existing calibration dataset, so that when users provide body measurements the regressor can produce dramatically more accurate betas.

#### Acceptance Criteria

1. THE Coefficient_Trainer SHALL train an Eight_Input_Regressor using the Calibration_Dataset, mapping normalized features (heightNorm, weightNorm, ageNorm, genderSign, chestNorm, waistNorm, hipNorm, inseamNorm) plus derived interaction terms (bmiNorm, waist-to-hip ratio, chest-to-waist ratio) to each of the 10 beta components
2. WHEN the Coefficient_Trainer fits the Eight_Input_Regressor on the Calibration_Dataset, THE resulting model SHALL achieve a mean absolute error of less than 0.15 beta units per component across 5-fold cross-validation (compared to the Four_Input_Regressor's threshold of 0.3)
3. THE Coefficient_Trainer SHALL export the Eight_Input_Regressor weights to the Extended_Coefficient_Table under a `regression8` key containing: intercepts (10), weights (10 × N_features), feature names, and normalization parameters (center, range) for each feature
4. THE Coefficient_Trainer SHALL continue to train and export the Four_Input_Regressor under the existing `regression` key, preserving backward compatibility
5. THE Coefficient_Trainer SHALL validate that the Eight_Input_Regressor reduces mean absolute error by at least 40% compared to the Four_Input_Regressor on the same cross-validation folds

### Requirement 2: Runtime 8-Input Regression Path

**User Story:** As a developer, I want `lookupRegress()` to use the 8-input model when custom measurements are available, so that the regressor produces betas that closely match the user's actual body shape.

#### Acceptance Criteria

1. WHEN the Extended_Coefficient_Table is loaded and the user provides all four custom measurements (chest, waist, hip, inseam), THE SMPL_Regressor SHALL use the Eight_Input_Regressor weights in `lookupRegress()` to compute betas from the full 8-input feature vector plus interaction terms
2. WHEN the Extended_Coefficient_Table is loaded but no custom measurements are provided, THE SMPL_Regressor SHALL use the existing Four_Input_Regressor weights in `lookupRegress()`, producing identical output to the current behavior
3. THE SMPL_Regressor SHALL compute each beta component in the 8-input path as: `β[i] = intercept8[i] + Σ(weight8[i][j] × normalizedFeature[j])` using the `regression8` coefficients and normalization parameters from the Extended_Coefficient_Table
4. THE 8-input `lookupRegress()` path SHALL produce beta vectors where all 10 components are finite numbers in the range [-3, 3] for any valid combination of inputs (height 140–210, weight 40–160, age 18–80, male/female, chest 60–150, waist 55–160, hip 65–160, inseam 55–100)
5. WHEN the `regression8` key is missing from the coefficient table (e.g., old coefficient file), THE SMPL_Regressor SHALL fall back to the Four_Input_Regressor path and log a warning

### Requirement 3: Hybrid Regression for Partial Measurements

**User Story:** As a user, I want to provide just one or two body measurements (e.g., only waist) and still get improved accuracy, so that I don't have to measure my entire body to benefit from the extended regressor.

#### Acceptance Criteria

1. WHEN the user provides 1–3 custom measurements (but not all four), THE SMPL_Regressor SHALL use the Hybrid_Regression strategy: impute missing measurements from demographics, then apply the Eight_Input_Regressor with the combined real + imputed inputs
2. THE Measurement_Imputer SHALL predict missing custom measurements using the ANSUR II lookup table when available, falling back to `predictMeasurementsFromDemographics()` when the lookup table is not loaded
3. WHEN the Hybrid_Regression path is used, THE SMPL_Regressor SHALL weight the real (user-provided) measurements more heavily than imputed values by applying a confidence scaling factor of 1.0 to real measurements and 0.7 to imputed measurements in the feature vector
4. THE Hybrid_Regression path SHALL produce betas that are strictly closer to the Eight_Input_Regressor output (when all measurements are known) than the Four_Input_Regressor output, for at least 90% of subjects in the Calibration_Dataset where the provided measurements match ground truth

### Requirement 4: Refinement Loop Improvement with 8-Input Initial Betas

**User Story:** As a developer, I want the refinement loop to converge faster when starting from 8-input betas, so that the avatar responds more quickly and accurately to custom measurement inputs.

#### Acceptance Criteria

1. WHEN the Eight_Input_Regressor produces the initial betas and custom measurements are provided, THE `refineWithCustomMeasurements()` loop SHALL converge (all measurement errors within 2cm of target) within 3 iterations for at least 90% of inputs in the moderate range (chest 80–120, waist 65–110, hip 85–125, inseam 70–90)
2. WHEN the Four_Input_Regressor produces the initial betas and custom measurements are provided, THE `refineWithCustomMeasurements()` loop SHALL continue to converge within 5 iterations as per the existing behavior (no regression)
3. THE `computeSmplBetas()` pipeline SHALL skip the refinement loop entirely when the Eight_Input_Regressor was used and all four custom measurements were provided, since the initial betas already incorporate the measurements directly — refinement is only needed for the Four_Input and Hybrid paths

### Requirement 5: Round-Trip Accuracy Targets with 8-Input Regression

**User Story:** As a developer, I want the 8-input regressor to achieve <5cm mean round-trip error and ≥80% of subjects within 5cm for all key measurements, so that the avatar accurately represents the user's body.

#### Acceptance Criteria

1. WHEN the Eight_Input_Regressor is used with ground-truth custom measurements from the ANSUR II validation set (100+ subjects), THE Round_Trip_Error for chest circumference SHALL have a mean of less than 5cm and at least 80% of subjects within 5cm
2. WHEN the Eight_Input_Regressor is used with ground-truth custom measurements, THE Round_Trip_Error for waist circumference SHALL have a mean of less than 5cm and at least 80% of subjects within 5cm
3. WHEN the Eight_Input_Regressor is used with ground-truth custom measurements, THE Round_Trip_Error for hip circumference SHALL have a mean of less than 5cm and at least 80% of subjects within 5cm
4. WHEN the Eight_Input_Regressor is used with ground-truth custom measurements, THE Round_Trip_Error for inseam length SHALL have a mean of less than 5cm and at least 80% of subjects within 5cm
5. THE validation test suite SHALL produce a comparison report showing per-measurement accuracy for both the Four_Input_Regressor (demographics-only) and the Eight_Input_Regressor (with measurements), demonstrating the improvement

### Requirement 6: Round-Trip Property for 8-Input Regressor

**User Story:** As a developer, I want property-based tests that verify the 8-input round-trip holds for random inputs, so that regressions are caught automatically.

#### Acceptance Criteria

1. THE test suite SHALL include a property-based test using fast-check that generates random valid 8-input combinations (height 150–200, weight 50–130, age 20–60, male/female, chest 75–130, waist 60–120, hip 80–135, inseam 65–95) and verifies the round-trip pipeline produces extracted measurements within 5cm of the input custom measurements
2. FOR ALL randomly generated 8-input combinations, THE round-trip chest circumference error (|extracted - input chestCm|) SHALL be less than 5cm
3. FOR ALL randomly generated 8-input combinations, THE round-trip waist circumference error SHALL be less than 5cm
4. FOR ALL randomly generated 8-input combinations, THE round-trip hip circumference error SHALL be less than 5cm
5. FOR ALL randomly generated 8-input combinations, THE round-trip inseam error SHALL be less than 5cm
6. THE property-based tests SHALL run with at least 50 iterations per property, using the SMPL model binary loaded once in a beforeAll hook

### Requirement 7: Training Script Dual-Model Export

**User Story:** As a developer, I want the training script to produce both 4-input and 8-input models in a single run, so that the coefficient table is self-contained and the runtime can select the appropriate model.

#### Acceptance Criteria

1. THE Coefficient_Trainer SHALL train both the Four_Input_Regressor and the Eight_Input_Regressor in a single execution of `python scripts/train-beta-coefficients.py`
2. THE Extended_Coefficient_Table SHALL contain both `regression` (4-input) and `regression8` (8-input) keys, each with their own intercepts, weights, features, and normalization parameters
3. THE Extended_Coefficient_Table SHALL remain under 100KB in size (minified JSON), accommodating the additional 8-input weights while staying browser-friendly
4. THE Coefficient_Trainer SHALL log a comparison summary showing the cross-validated MAE for both models side-by-side, confirming the 8-input model's improvement
5. WHEN `npm run calibrate` is executed, THE pipeline SHALL produce the Extended_Coefficient_Table containing both models

### Requirement 8: Coefficient Table Schema Extension

**User Story:** As a developer, I want the coefficient table schema to be versioned and extended cleanly, so that old coefficient files still work and new files are self-describing.

#### Acceptance Criteria

1. THE Extended_Coefficient_Table SHALL use version `"2.0.0"` to distinguish it from the current `"1.0.0"` format that lacks the `regression8` key
2. WHEN the SMPL_Regressor loads a version `"1.0.0"` coefficient table (missing `regression8`), THE SMPL_Regressor SHALL use only the Four_Input_Regressor and log an informational message that the 8-input model is not available
3. WHEN the SMPL_Regressor loads a version `"2.0.0"` coefficient table, THE SMPL_Regressor SHALL accept both `"1.0.0"` and `"2.0.0"` as valid versions, using the `regression8` key when present
4. THE `CalibratedCoefficients` TypeScript interface SHALL be extended with an optional `regression8` field matching the same structure as `regression` but with the 8-input feature set
5. THE Extended_Coefficient_Table SHALL include a `regression8.features` array listing all feature names in order, so the runtime can validate feature alignment

### Requirement 9: Backward Compatibility

**User Story:** As a user, I want the 4-input demographics-only path to remain unchanged, so that existing behavior is preserved when I don't provide custom measurements.

#### Acceptance Criteria

1. WHEN no custom measurements are provided (all null/undefined), THE SMPL_Regressor SHALL produce identical beta output to the current implementation using the Four_Input_Regressor
2. THE SMPL_Regressor SHALL maintain the same public API: `computeSmplBetas(inputs, model?)` returning `Float64Array(10)`, `lookupRegress(inputs)` returning `Float64Array(10)`, and all existing exported types and interfaces
3. THE SMPL_Regressor SHALL maintain the same layered pipeline order: base regression → preset offsets → composition bias → custom measurement refinement → clamp [-3, 3]
4. THE existing property-based tests (`smplRegressor.prop.test.ts`) SHALL continue to pass with the Extended_Coefficient_Table loaded
5. THE existing unit tests (`smplRegressor.unit.test.ts`) SHALL continue to pass without modification
6. IF the Extended_Coefficient_Table is not present, THEN THE SMPL_Regressor SHALL fall back to heuristic coefficients, producing identical output to the pre-calibration implementation

### Requirement 10: Parse and Print Round-Trip for Coefficient Table

**User Story:** As a developer, I want the coefficient table to survive a parse → serialize → parse round-trip without data loss, so that tooling can safely read and rewrite the file.

#### Acceptance Criteria

1. FOR ALL valid Extended_Coefficient_Table JSON files, parsing the JSON then serializing it back to JSON then parsing again SHALL produce an object with identical regression weights, intercepts, and normalization parameters (within floating-point precision of 1e-10)
2. THE round-trip property SHALL hold for both the `regression` (4-input) and `regression8` (8-input) sections of the coefficient table
3. THE test suite SHALL include a property-based test that generates random valid coefficient table structures and verifies the parse → serialize → parse round-trip
