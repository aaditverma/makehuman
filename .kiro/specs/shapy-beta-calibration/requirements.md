# Requirements Document

## Introduction

Replace the heuristic coefficients in the SMPL regressor (`src/utils/smplRegressor.ts`) with data-driven coefficients calibrated against real body data. The current layered beta pipeline (lookupRegress → presetOffsets → compositionBias → customMeasurementRefinement → clamp) uses hand-tuned coefficients that produce directionally correct but magnitude-inaccurate body shapes. This spec implements two complementary calibration approaches:

1. **SHAPY Synthetic Training Data**: Use the SHAPY regressor (https://github.com/muelea/shapy) to generate a large synthetic dataset mapping anthropometric measurements to ground-truth SMPL beta parameters. Train a lightweight coefficient table from this data that replaces the heuristic coefficients in `lookupRegress()`.

2. **Manual Beta Calibration via Forward Pass**: Run the SMPL forward pass on known body shapes (from ANSUR II and NHANES population data), extract mesh measurements using `measurementExtractor.ts`, and validate/tune the regressor coefficients against ground-truth anthropometric measurements. This closes the loop: measurements → betas → mesh → extracted measurements ≈ original measurements.

The end result is a regressor where entering height/weight/measurements produces an SMPL avatar whose mesh-extracted measurements closely match the input, replacing guesswork with data.

## Glossary

- **SHAPY_Regressor**: The SHAPY open-source tool (CVPR 2022, https://github.com/muelea/shapy) that regresses SMPL body shape parameters from anthropometric measurements and semantic attributes. Runs as a Python process, not in the browser.
- **Synthetic_Training_Pair**: A single (measurements, betas) data point generated by SHAPY, where measurements are anthropometric inputs (height, weight, chest, waist, hip, etc.) and betas are the 10 SMPL shape coefficients that SHAPY predicts for those measurements.
- **Calibration_Dataset**: The complete collection of Synthetic_Training_Pairs generated by the SHAPY_Data_Generator, stored as a JSON file for offline training.
- **SHAPY_Data_Generator**: A Python script (`scripts/generate-shapy-data.py`) that invokes SHAPY to produce Synthetic_Training_Pairs across a grid of anthropometric inputs covering the population range.
- **Calibrated_Coefficients**: The data-driven regression coefficients that replace the heuristic values in `lookupRegress()`, derived from fitting a linear or polynomial model to the Calibration_Dataset.
- **Coefficient_Table**: A JSON file (`src/data/calibrated_coefficients.json`) containing the Calibrated_Coefficients, loaded at runtime by the SMPL_Regressor.
- **Coefficient_Trainer**: A Python script (`scripts/train-beta-coefficients.py`) that fits a regression model to the Calibration_Dataset and exports the Coefficient_Table.
- **Forward_Pass_Validator**: A TypeScript module or test suite that runs the SMPL forward pass with known beta vectors, extracts measurements from the resulting mesh, and compares them against expected anthropometric values.
- **Round_Trip_Error**: The absolute difference (in cm) between an input measurement and the measurement extracted from the SMPL mesh after the full pipeline: input → regressor → betas → forward pass → mesh → measurement extraction.
- **ANSUR_II_Dataset**: The US Army Anthropometric Survey II dataset (6,068 subjects, 93 measurements) used as ground-truth body measurement data for validation.
- **NHANES_Dataset**: The National Health and Nutrition Examination Survey 2011–2018 dataset (22,468 subjects, height/weight/waist/hip) used for validation across the general population.
- **SMPL_Regressor**: The `smplRegressor.ts` module containing `lookupRegress()`, `computeSmplBetas()`, and the layered beta pipeline.
- **Measurement_Extractor**: The `measurementExtractor.ts` module that computes circumferences from the deformed SMPL mesh at anatomical cross-sections.
- **SMPL_Forward_Pass**: The `smplForwardPass.ts` module that computes vertex positions from beta parameters: V = T + Σ(βᵢ × Sᵢ).
- **Population_Grid**: A systematic grid of anthropometric inputs (height 140–210cm, weight 40–160kg, ages 20–60, both genders) used to generate the Calibration_Dataset and validate coverage.
- **Sensitivity_Map**: The `MEASUREMENT_BETA_MAP` in `smplRegressor.ts` that maps each measurement key to the beta components it affects and their sensitivity coefficients. Currently heuristic, to be replaced with data-driven values.
- **Preset_Offset_Vector**: The additive beta offset for each body type preset (Slim, Average, Athletic, Curvy, Heavy) stored in `SMPL_PRESET_OFFSETS`. To be recalibrated using SHAPY data.
- **Composition_Bias_Vector**: The additive beta offset for each body composition (Athletic, Average, Heavy) stored in `COMPOSITION_BIAS`. To be recalibrated using SHAPY data.

## Requirements

### Requirement 1: SHAPY Synthetic Data Generation

**User Story:** As a developer, I want to generate a large dataset of (measurements → betas) pairs using SHAPY, so that I have ground-truth data to train calibrated regressor coefficients.

#### Acceptance Criteria

1. THE SHAPY_Data_Generator SHALL produce Synthetic_Training_Pairs by invoking SHAPY for each point on the Population_Grid (height 140–210cm in 5cm steps, weight 40–160kg in 5kg steps, ages [20, 30, 40, 50, 60], both genders)
2. WHEN SHAPY is invoked with a set of anthropometric measurements, THE SHAPY_Data_Generator SHALL capture the 10-element SMPL beta vector that SHAPY produces and store it alongside the input measurements
3. THE SHAPY_Data_Generator SHALL store the Calibration_Dataset as a JSON file with each entry containing: heightCm, weightKg, age, gender, chestCm, waistCm, hipCm, shoulderCm, inseamCm, and the 10 betas
4. THE SHAPY_Data_Generator SHALL use the ANSUR_II_Dataset lookup table to supply chest, waist, hip, shoulder, and inseam values for each Population_Grid point (interpolating where grid points fall between lookup entries)
5. IF SHAPY fails to produce a valid beta vector for a grid point (error, timeout, or NaN values), THEN THE SHAPY_Data_Generator SHALL log the failure and skip that entry without halting the generation process
6. THE Calibration_Dataset SHALL contain a minimum of 5,000 valid Synthetic_Training_Pairs covering the full Population_Grid range

### Requirement 2: Coefficient Training from SHAPY Data

**User Story:** As a developer, I want to train calibrated regression coefficients from the SHAPY dataset, so that the TypeScript regressor produces accurate betas without running SHAPY at runtime.

#### Acceptance Criteria

1. THE Coefficient_Trainer SHALL fit a regression model mapping normalized inputs (heightCm, weightKg, age, gender, BMI) to each of the 10 beta components using the Calibration_Dataset
2. THE Coefficient_Trainer SHALL export the Calibrated_Coefficients as a JSON Coefficient_Table containing: per-beta linear weights for each input feature, per-beta intercept terms, and normalization parameters (center, range) for each input
3. WHEN the Coefficient_Trainer is run on the Calibration_Dataset, THE resulting model SHALL achieve a mean absolute error of less than 0.3 beta units per component across the training set (cross-validated)
4. THE Coefficient_Trainer SHALL also fit calibrated Sensitivity_Map entries (measurement key → beta indices + sensitivities) by analyzing the partial derivatives of betas with respect to each measurement in the Calibration_Dataset
5. THE Coefficient_Table SHALL be loadable by the TypeScript SMPL_Regressor at runtime without any Python dependencies

### Requirement 3: Regressor Coefficient Replacement

**User Story:** As a developer, I want to replace the heuristic coefficients in `lookupRegress()` with the calibrated coefficients, so that the regressor produces accurate betas for any user input.

#### Acceptance Criteria

1. WHEN the Coefficient_Table is available at runtime, THE SMPL_Regressor SHALL load the Calibrated_Coefficients and use them in `lookupRegress()` instead of the hardcoded heuristic coefficients
2. IF the Coefficient_Table fails to load (missing file, parse error), THEN THE SMPL_Regressor SHALL fall back to the existing heuristic coefficients and log a warning
3. THE calibrated `lookupRegress()` SHALL compute each beta component as: `β[i] = intercept[i] + Σ(weight[i][j] × normalizedInput[j])` using the coefficients and normalization parameters from the Coefficient_Table
4. THE calibrated `lookupRegress()` SHALL produce beta vectors where all 10 components are finite numbers in the range [-3, 3] for any valid user input (height 140–210, weight 40–160, age 18–80, male or female)
5. THE SMPL_Regressor SHALL replace the heuristic `MEASUREMENT_BETA_MAP` sensitivities with the data-driven Sensitivity_Map from the Coefficient_Table, preserving the same interface for `refineWithCustomMeasurements()`

### Requirement 4: Preset and Composition Offset Recalibration with Dramatic Visual Distinction

**User Story:** As a user, I want switching between Athletic, Average, and Heavy body compositions to produce an obviously different body shape on the avatar, so that the composition selector feels meaningful and I can clearly see the difference between a muscular build and a soft build at the same weight.

#### Acceptance Criteria

1. THE Coefficient_Trainer SHALL compute calibrated Preset_Offset_Vectors by generating SHAPY betas for representative body shapes of each preset type (e.g., Slim: low BMI subjects, Athletic: high shoulder-to-waist ratio subjects, Heavy: high BMI subjects) and computing the mean beta difference from the Average baseline
2. THE Coefficient_Trainer SHALL compute calibrated Composition_Bias_Vectors by generating SHAPY betas for subjects with known body composition differences (muscular vs soft builds at the same BMI) and computing the mean beta difference from the Average baseline
3. WHEN the Coefficient_Table is loaded, THE SMPL_Regressor SHALL use the calibrated Preset_Offset_Vectors in `SMPL_PRESET_OFFSETS` instead of the hardcoded values
4. WHEN the Coefficient_Table is loaded, THE SMPL_Regressor SHALL use the calibrated Composition_Bias_Vectors in `COMPOSITION_BIAS` instead of the hardcoded values
5. THE calibrated Preset_Offset_Vectors SHALL preserve the qualitative behavior: Slim produces a leaner body, Athletic produces wider shoulders and thicker limbs, Heavy produces a larger torso, and Curvy produces wider hips relative to waist
6. WHEN the user switches from Average to Athletic composition at the same height and weight, THE resulting SMPL mesh SHALL show a shoulder circumference increase of at least 3cm, a waist circumference decrease of at least 2cm, and a bicep circumference increase of at least 1.5cm as measured by the Measurement_Extractor
7. WHEN the user switches from Average to Heavy composition at the same height and weight, THE resulting SMPL mesh SHALL show a waist circumference increase of at least 4cm, a hip circumference increase of at least 2cm, and a belly depth increase visible as increased β1 by at least 0.4 units
8. WHEN the user switches between Athletic and Heavy composition at the same height and weight, THE L2 distance between the two beta vectors SHALL be at least 0.8 (current threshold is 0.1, which is too subtle), producing a body shape difference that is immediately obvious to the user without side-by-side comparison
9. THE Composition_Bias_Vectors SHALL affect at least 6 of the 10 beta components (not just 2–3), ensuring that the composition change impacts shoulders, chest, waist, hips, arms, and legs — producing a whole-body transformation rather than a localized tweak
10. WHEN the Athletic composition is selected, THE SMPL_Regressor SHALL produce a shoulder-to-waist ratio (shoulder circumference / waist circumference) that is at least 0.05 higher than the Average composition ratio for the same inputs, reflecting the V-taper characteristic of muscular builds

### Requirement 5: Forward Pass Validation Pipeline

**User Story:** As a developer, I want to validate the calibrated regressor by running the full round-trip pipeline (measurements → betas → mesh → extracted measurements) against known body data, so that I can verify accuracy end-to-end.

#### Acceptance Criteria

1. THE Forward_Pass_Validator SHALL run the full pipeline for a validation set of at least 100 subjects sampled from the ANSUR_II_Dataset: input measurements → `computeSmplBetas()` → `computeSmplVertices()` → `extractMeasurements()` → compare with original ANSUR measurements
2. WHEN the Forward_Pass_Validator runs the round-trip pipeline on a validation subject, THE Round_Trip_Error for chest, waist, and hip circumferences SHALL be less than 5cm for at least 80% of subjects
3. WHEN the Forward_Pass_Validator runs the round-trip pipeline on a validation subject, THE Round_Trip_Error for inseam length SHALL be less than 5cm for at least 80% of subjects
4. THE Forward_Pass_Validator SHALL produce a summary report containing: per-measurement mean Round_Trip_Error, median Round_Trip_Error, 90th percentile error, and percentage of subjects within 3cm and 5cm tolerance
5. THE Forward_Pass_Validator SHALL be runnable as a Vitest test suite that loads the SMPL model binary, runs the pipeline on validation subjects, and asserts the accuracy thresholds
6. IF the Round_Trip_Error exceeds 5cm for more than 20% of subjects on any measurement, THEN THE Forward_Pass_Validator SHALL flag the measurement as needing further calibration

### Requirement 6: Round-Trip Property for Regressor

**User Story:** As a developer, I want a property-based test that verifies the regressor round-trip (measurements → betas → mesh → measurements ≈ original) holds for random inputs, so that regressions are caught automatically.

#### Acceptance Criteria

1. THE test suite SHALL include a property-based test using fast-check that generates random valid inputs (height 150–200, weight 50–130, age 20–60, male/female) and verifies the round-trip pipeline produces extracted measurements within a defined tolerance of the ANSUR-predicted measurements for those inputs
2. FOR ALL randomly generated inputs, THE round-trip chest circumference error SHALL be less than 8cm (allowing for measurement extraction approximation on top of regressor error)
3. FOR ALL randomly generated inputs, THE round-trip waist circumference error SHALL be less than 8cm
4. FOR ALL randomly generated inputs, THE round-trip hip circumference error SHALL be less than 8cm
5. THE property-based test SHALL run with at least 50 iterations per property, using the SMPL model binary loaded once in a beforeAll hook

### Requirement 7: Sensitivity Map Calibration

**User Story:** As a developer, I want the measurement-to-beta sensitivity map to reflect actual SMPL shape space relationships, so that custom measurement refinement converges accurately.

#### Acceptance Criteria

1. THE Coefficient_Trainer SHALL compute the Sensitivity_Map by perturbing each measurement input by ±5cm in the Calibration_Dataset and measuring the resulting beta changes, producing a sensitivity coefficient (beta change per cm) for each (measurement, beta) pair
2. THE calibrated Sensitivity_Map SHALL include entries for at least: bustCm, waistCm, hipCm, and inseamCm, each mapping to the beta indices with sensitivity magnitude greater than 0.02 per cm
3. WHEN the calibrated Sensitivity_Map is used in `refineWithCustomMeasurements()`, THE refinement loop SHALL converge (all measurement errors within 3cm of target) within 5 iterations for at least 90% of inputs in the moderate range (bust 80–120, waist 65–110, hip 85–125, inseam 70–90)
4. THE calibrated Sensitivity_Map SHALL be stored in the Coefficient_Table alongside the regression coefficients, using the same JSON format

### Requirement 8: Manual Beta Calibration via Known Body Shapes

**User Story:** As a developer, I want to run the SMPL forward pass on known body shapes from ANSUR II data, measure the resulting meshes, and compare against ground-truth measurements, so that I can identify and correct systematic biases in the regressor.

#### Acceptance Criteria

1. THE Forward_Pass_Validator SHALL include a calibration mode that processes a curated set of at least 50 ANSUR II subjects spanning the BMI range 18–35, both genders, and ages 20–55
2. WHEN running in calibration mode, THE Forward_Pass_Validator SHALL compute per-measurement bias (mean signed error) and per-measurement scale factor (ratio of extracted to ground-truth measurement) across the calibration set
3. IF the per-measurement bias exceeds 2cm for any measurement, THEN THE Forward_Pass_Validator SHALL output a correction factor that can be applied to the Coefficient_Table to reduce the bias
4. THE Forward_Pass_Validator SHALL output the correction factors as a JSON patch file that the Coefficient_Trainer can merge into the Coefficient_Table
5. WHEN correction factors are applied to the Coefficient_Table, THE Round_Trip_Error for the corrected measurements SHALL decrease compared to the uncorrected Coefficient_Table (verified by re-running the validation pipeline)

### Requirement 9: Regressor Coefficient Serialization and Loading

**User Story:** As a developer, I want the calibrated coefficients to be serialized in a compact, versioned format that loads efficiently at runtime, so that the browser app starts quickly and can detect stale coefficients.

#### Acceptance Criteria

1. THE Coefficient_Table JSON SHALL include a version field (semantic version string) and a generatedAt timestamp, so that the SMPL_Regressor can detect when coefficients are outdated
2. THE Coefficient_Table SHALL be less than 50KB in size (minified JSON), ensuring fast loading in the browser
3. THE Coefficient_Trainer SHALL produce the Coefficient_Table in a single `npm run calibrate` command that runs the full pipeline: generate SHAPY data → train coefficients → validate → export
4. WHEN the Coefficient_Table version does not match the expected version in the SMPL_Regressor, THE SMPL_Regressor SHALL log a warning and fall back to heuristic coefficients
5. THE Coefficient_Table JSON format SHALL be documented with a TypeScript interface (`CalibratedCoefficients`) that the SMPL_Regressor imports for type-safe loading

### Requirement 10: Fat Distribution Modeling

**User Story:** As a user, I want the SMPL avatar to show realistic fat distribution patterns when I change my weight, so that the body shape reflects where fat actually accumulates based on my gender, age, and body type — and I can see the difference between a muscular 90kg person and a soft 90kg person.

#### Acceptance Criteria

1. THE Coefficient_Trainer SHALL extract fat distribution patterns from the Calibration_Dataset by analyzing how beta components change across BMI ranges (18–35) for each gender, identifying which betas control android (belly-dominant) vs gynoid (hip/thigh-dominant) fat deposition
2. WHEN the user increases weight for a male body, THE calibrated SMPL_Regressor SHALL increase belly-related betas (β1 weight/BMI, β5 torso width) proportionally more than hip-related betas (β7), reflecting the android fat distribution pattern typical of male bodies
3. WHEN the user increases weight for a female body, THE calibrated SMPL_Regressor SHALL increase hip and thigh-related betas (β7 hip width, β9 leg thickness) proportionally more than belly-related betas, reflecting the gynoid fat distribution pattern typical of female bodies
4. WHEN the user's age is above 40, THE calibrated SMPL_Regressor SHALL shift fat distribution toward android patterns (increased β1, β5 relative to β7) compared to the same height/weight at age 25, reflecting age-related redistribution of body fat
5. THE Coefficient_Table SHALL include per-gender fat distribution weight vectors that modulate how weight changes map to individual beta components, replacing the current uniform BMI-to-beta scaling in `lookupRegress()`
6. WHEN the user selects Athletic body composition at a given weight, THE calibrated SMPL_Regressor SHALL distribute less of the weight increase to belly betas (β1, β5) and more to limb betas (β8, β9) compared to Heavy composition at the same weight, reflecting the difference between muscular and adipose tissue distribution
7. WHEN comparing a 175cm/90kg Athletic male to a 175cm/90kg Heavy male, THE resulting SMPL meshes SHALL differ by at least 5cm in waist circumference and at least 2cm in bicep circumference as measured by the Measurement_Extractor, making the muscular vs soft distinction clearly visible on the avatar
8. THE fat distribution model SHALL produce a continuous gradient of body shape changes as weight increases from 50kg to 130kg (at fixed height), with no sudden jumps or discontinuities in any beta component greater than 0.3 units per 5kg weight increment

### Requirement 11: Height-Weight Interaction Modeling

**User Story:** As a developer, I want the regressor to model non-linear height-weight interactions, so that a tall heavy person and a short heavy person at the same weight produce realistically different body proportions.

#### Acceptance Criteria

1. THE Coefficient_Trainer SHALL include BMI and height-weight interaction terms (heightCm × weightKg, heightCm², BMI²) in the regression model, capturing non-linear relationships between body dimensions and SMPL betas
2. WHEN two users have the same weight but different heights (e.g., 160cm/90kg vs 185cm/90kg), THE calibrated SMPL_Regressor SHALL produce visibly different body shapes: the shorter user SHALL have a wider torso (higher β1, β5) and the taller user SHALL have a leaner torso with longer limbs
3. THE calibrated `lookupRegress()` SHALL compute beta components using at least these normalized input features: heightNorm, weightNorm, ageNorm, genderSign, bmiNorm, and the interaction term heightNorm × weightNorm
4. WHEN the user changes height while keeping weight constant, THE calibrated SMPL_Regressor SHALL adjust body proportions (not just Y-scale): increasing height SHALL reduce torso width betas and increase limb proportion betas, producing a leaner silhouette
5. THE Coefficient_Trainer SHALL validate that the interaction model reduces Round_Trip_Error compared to a linear-only model by at least 10% on the validation set, justifying the added complexity

### Requirement 12: Backward Compatibility

**User Story:** As a user, I want the calibrated regressor to produce the same or better body shapes for my existing inputs, so that upgrading does not break my experience.

#### Acceptance Criteria

1. WHEN the calibrated SMPL_Regressor is used with the same inputs as the heuristic regressor, THE resulting body shape SHALL be visually reasonable (no collapsed geometry, no extreme distortions, all betas in [-3, 3])
2. THE SMPL_Regressor SHALL maintain the same public API: `computeSmplBetas(inputs, model?)` returning `Float64Array(10)`, `lookupRegress(inputs)` returning `Float64Array(10)`, and all existing exported types and interfaces
3. THE SMPL_Regressor SHALL maintain the same layered pipeline order: base regression → preset offsets → composition bias → custom measurement refinement → clamp [-3, 3]
4. IF the Coefficient_Table is not present (e.g., in development or testing), THEN THE SMPL_Regressor SHALL produce identical output to the current heuristic implementation, ensuring zero regression for existing users
5. THE existing property-based tests (smplRegressor.prop.test.ts) SHALL continue to pass with the calibrated coefficients loaded
